# practice

Translation practice on an FSRS schedule: each word's card and due date, the daily allowance of new words and their priorities, the practice sets (a session's cards, at most 10: a set of New words and a set of the review words owed today, kept apart), the frequency list that ranks words, the review log of graded answers, the struggling-words drill (words whose latest answer was again or hard, read only), the practice reset, the practice settings, and the same schedule for phrases (their own card, set of at most 10 and review log, without priorities or word errors). Pure scheduling, allocation and set rules have no I/O. Repositories hold the SQL only, services own the rules, and adapters expose the practice to REST and MCP. Dictionary CRUD and the old drill stay in `domains/words/`, and the frequency list file is read by the import script, not here.

## Files

| File | What it does |
|---|---|
| `practice-repository.js` | SQL for `practice_settings` (JSON values), the card, due, introduction and priority columns of `words` (read through `v_words`), the two deck directions of `words`, the count of overdue words, the struggling words (each word whose latest review log counts as again or hard in its session: the worse of its two grades), `review_logs` (`findLatestReviewLogSince`: the word's latest log of the day, any session, that still counts, `superseded_at` NULL; `updateReviewLogSecondGrade` stores the first answer in the other direction), and `deck_answers` per direction (`listAnsweredDirectionsSince` for the set's directions). `markReviewLogsSuperseded` and `markDeckAnswersSuperseded` mark them at a practice reset. No business rules. |
| `practice-direction.js` | Pure: the two directions of practice, `uk_nl` (the Ukrainian is shown, the Dutch is answered) and `nl_uk` (the reverse), `PRACTICE_DIRECTIONS`, `findOtherDirection` and `findWorseGrade` (again < hard < good). |
| `phrase-practice-repository.js` | SQL for the card, due, introduction and status columns of `phrases`, and `phrase_review_logs` (`findLatestPhraseReviewLogSince`: the phrase's latest log of the day that still counts; `markPhraseReviewLogsSuperseded` marks them at a practice reset). No business rules. |
| `frequency-repository.js` | SQL for `word_frequencies`: replaces or upserts the rank of each word form, looks up a rank by form, case-insensitively, and lists the forms up to a rank (`listFrequencyRowsUpToRank`, for the missing-word suggestions). No transactions; the service wraps them. |
| `practice-calendar.js` | Pure: calendar dates in the practice time zone (`Europe/Amsterdam`), start of a day and day arithmetic, DST-safe. Builds one `Intl` formatter per time zone and reuses it. |
| `fsrs-scheduling.js` | Pure wrapper around ts-fsrs: grades a card, serializes and parses cards, reads the scheduled interval, derives the learning status and the state name (from `CARD_STATE_VALUES`), builds the migration cards. |
| `priority-calculation.js` | Pure: parses the chapter from a section code, calculates a word's priority 1–3 from its effective rank (the frequency rank halved for the current and previous chapter; 2000 → P1, 5000 → P2), maps the manual tag ('first', 'later') to the override and back, compares queue order («Вчити першим» first, then effective rank) and computes a frequency rank for a Dutch text (apostrophes kept, numbers ignored, names in expressions unranked). |
| `new-word-allocation.js` | Pure: `calculateNewWordAllowance({ newPerDay, tierQuota, blockSize })` gives the tier quota of a block (each quota scaled by the block size and rounded down: 10 gives 7, 2, 1; 20 gives 14, 4, 2), and `allocateNewWords` chooses the New words of a block by priority quota, with unused slots going to P1, P2, P3, and the topic caps of a set (at most 3 words of one category, 2 expressions; «Вчити першим» exempt; capped candidates fill in last). |
| `practice-set.js` | Pure: the practice set of a session, at most `new_per_day` (10) cards. A word set has a kind: `NEW_SET_KIND` ('new', New words only, saved as `word_set`) or `REVIEW_SET_KIND` ('review', the words owed today, saved as `review_set`); `SET_KINDS`, `assertSetKind` and `readSetOfKind` pick the stored set of a kind. `planSetRoom` puts the old cards first (phrases: no repeats, up to the set size) and returns the room left for new cards; `findOpenSet` keeps a set open while it was opened today and an item is still pending, with its `pendingIds` in pinned order; `openPracticeSet` pins items, `mapToStoredSet` and `mapFromStoredSet` convert to and from the saved `{ opened_on, opened_at, item_ids }`. |
| `review-set-planning.js` | Pure: the review set's order. `mapToReviewCandidate` reads a word row's priority, FSRS difficulty and lapses (from its card, 0 without one), due time, introduction day and id; `compareReviewOrder` puts priority 1, 2, 3 first, then the harder word (difficulty, then lapses, higher first), then the earlier due time, then the id; `orderReviewCandidates` leaves out the words introduced today and the excluded ids (graded in this session) and returns the rest in that order. |
| `migration-planning.js` | Pure: `planMigration` plans the one-time FSRS migration without writing (learning words spread over the next four days, most errors first; learned words due in 21 days; new words stay new) and `summarizeMigration` gives the counts the dry run and the real run both return. |
| `learning-deck.js` | Pure learning-deck rules (the deck is the current session's words), per direction. `applyAnswerToDeck` moves one direction for one answer (a word enters on its first answer ever, or on a lapse, which it remembers as `isLapse`; good adds a right answer, again or hard add one required right answer up to 6 and keep the right answers given; the right answers reaching the required count means learned), `applyAnswerToDecks` applies an answer to `{ uk_nl, nl_uk }` (the first answer ever enters both directions), `countTimesLeft`, `readDeckPosition` and `readReverseDeckPosition` (from the `deck_*` and `deck_reverse_*` columns), `readDeckPositions`, `describeDeckPosition` and `describeDeckPositions` (the `deck` fields of the adapters: `in_deck`, `times_left`, `uk_nl`, `nl_uk`) and `replayDeckAnswers` (for the rebuild). |
| `known-check-planning.js` | Pure: `listKnownCheckCandidates` gives the New words the quick known check asks about, in the queue order of `word-set-planning.js` (`compareQueueOrder` on `mapToQueueCandidate`), without the words already shown and without today's open set; `spreadKnownCheckDays(count)` gives the day offsets (14 to 28, evenly) of the words marked known. |
| `known-check-service.js` | Service: `getKnownCheck({ limit })` lists the next New words (`words`, `remaining`); `recordKnownCheck({ knownIds, unknownIds })` gives each known word a learned review card (`buildMigrationCard({ group: 'learned' })`, due 14 to 28 days, status `learned`, introduced today, no deck places) and remembers the unknown ones in `known_check_seen`. Ids that are not New words or are in today's set are ignored; one word in both lists is refused. No answer, review log, statistic or achievement is written. Publishes `words` after a write. |
| `word-set-planning.js` | Factory `createWordSetPlanner({ practiceRepository })`: `planWordSet({ settings, today, gradedWordIds, kind })` returns the open set of the kind's words not finished yet, or plans the next set of that kind (`kind` defaults to 'new'). The 'new' set is New words by priority quota (7, 2, 1 scaled to the set size), nothing else. The 'review' set is the deck's words and the reviews due before tomorrow, through `review-set-planning.js` (today's New words and the ones graded in this session left out), the first 10 in review order. A word of an open set is finished when it is in neither deck direction and was answered in both directions since the set opened. `countReviewWordsOwed` counts the review words owed today (the open review set included), `countNewWordsOutside` counts the New words waiting outside a set, per priority. Pure helpers: `isWordPending`, `listDirectionsLeft` (the `directions_left` of a card) and `mapAnsweredDirections`. `planSpareWords({ …, kind })` gives the spare words of the next set of that kind (New words by quota, or the review words owed), without the current set and the session's graded words. Reads only; writes nothing. |
| `practice-settings.js` | Service: reads the practice settings in camelCase (`readSettings`: `newPerDay` is the set size for words and phrases, `dailyGoal` the daily answer goal (default 20, `saveDailyGoal`); the pinned sets `wordSet` (New words), `reviewSet` (review words) and `phraseSet` as `{ openedOn, openedAt, itemIds }`, null when none is stored (`saveWordSet`, `saveReviewSet`, `savePhraseSet`); `knownCheckSeen`, the ids the quick known check showed as unknown, and `knownCheckKnown`, the ids marked known (the achievements leave them out), with `saveKnownCheckSeen` / `saveKnownCheckKnown`; `priorityRulesVersion`); `readActiveSettings` is the one guard that refuses practice before the FSRS migration. Saves the current chapter and the sets, tells whether FSRS is active and records the migration time. |
| `priority-service.js` | Service: recalculates priorities (`recalculatePriorities` publishes; `recalculatePrioritiesInTransaction` is for a caller that already holds a transaction and publishes nothing), ranks words from the frequency list (`assignNewWordRanking` also runs inside the caller's transaction), makes a later chapter of added words the current one (`followChapterOfAddedWords`, same transaction; at most two chapters ahead, so a typo does not move it), reads and sets the current chapter, runs the one-off recalculation when `priority_rules_version` is below 2 (`upgradePriorityRules`, called at start-up), sets manual priorities, previews priorities for a chapter, and imports the frequency list in one transaction. Publishes `words` changes. |
| `practice-service.js` | Service: builds the practice batch of a kind (`getPracticeBatch({ sessionId, maxReviews, kind })`: the session's set of that kind, at most 10 words; `counts.kind`, `set_size`, `set_words`, `set_new_words`, `is_set_open`, `review_owed`, `introduced_today`; each word has `directions_left`), pins the planned set when it is shown (the set of a word's kind when a first answer pins one: a word without a card is a 'new' set word, any other a 'review' one), grades a word in a direction (`gradeWord({ wordId, grade, answer, sessionId, direction })`: the first answer of a session is the FSRS grade and review log; the first answer in the other direction sets the log's second grade and grades FSRS again from the card the session started with when it is worse; any later answer moves only the deck; a New word outside the open set is refused; a wrong grade is recorded through `wordService.recordPracticeError`), summarises the pinned set of a kind (`getRoundSummary({ kind })`, the answers since the set opened), lists the struggling words (`listStrugglingWords`, read only), rebuilds the uk_nl deck (`rebuildLearningDeck`), runs the migration to FSRS (dry run or real; one transaction, one `words` change after the commit) and calculates the practice statistics, with the phrases' own numbers under `phrases`. Publishes `words` changes. |
| `practice-reset-service.js` | Service: `resetPractice({ isDryRun })` starts the practice over: every word and phrase with a card, due date or introduction goes back to New, both decks in both directions are cleared, the practice sets (the New words set, the review set and the phrase set) are cleared and every review log, deck answer and phrase answer that still counts is superseded, all in one transaction (the scheduled rows are read inside it); review logs and word errors are kept. Refused before the FSRS migration. Publishes `words` and `phrases` changes after a real reset. |
| `phrase-practice-service.js` | Service: the phrase batch (the session's phrase set: at most 10 phrases, phrases due today first, most overdue first, then the oldest New phrases in the room left; a pinned set stays until each phrase is graded that day), pinning a planned set when it is shown, grading a phrase once per session (a New phrase outside the open set is refused), and the phrase statistics. Gated by the same `readActiveSettings` guard as words. Publishes `phrases` changes. |
| `practice-tools.js` | MCP adapter: registers the twelve practice tools (`get_practice_batch` with an optional `kind` 'new' (default) or 'review', `grade_word`, `get_phrase_batch`, `grade_phrase`, `set_current_chapter`, `set_word_priority`, `import_frequency_list`, `preview_priorities`, `migrate_to_fsrs`, `reset_practice`, `practice_stats`, `get_struggling_words`). `set_word_priority` returns the compact word of the word tools, with `priority_override` and `priority_tag`; `get_struggling_words` is read only. |
| `round-summary.js` | Pure: the round's words with answers, mistakes per direction (`mistakes: { uk_nl, nl_uk }`) and difficulty, a word learned when both directions are finished, the hardest word, and the time spent without pauses. |
| `client-answer-receipts.js` | SQL for `client_answer_receipts`: the response of each grade or drill answer sent with a `client_answer_id` (kept 30 days). The practice service writes a receipt in the same transaction as the answer, so a repeated post returns the stored response and writes nothing. |
| `practice-routes.js` | REST adapter: `GET /api/practice/chapter` and `PUT /api/practice/chapter { chapter }` (the current chapter; PUT recalculates priorities), `GET /api/practice/batch?kind=new|review` (default `new`), `POST /api/practice/grades` (optional `client_answer_id`, `answered_at`, `set_word_ids`: the offline fields, REST only), `GET /api/practice/phrases/batch`, `POST /api/practice/phrases/grades`, `GET /api/practice/stats`, `GET /api/practice/struggling-words` (read only), `GET /api/practice/spare-words?kind=` (read only: the words for the phone's next offline set of that kind), `GET /api/practice/round-summary?kind=` (read only, the set of that kind), `GET /api/practice/priorities/preview`, `POST /api/practice/drill-answers` (same offline fields), `GET /api/practice/known-check?limit=` (the next New words of the quick known check) and `POST /api/practice/known-check { known_ids, unknown_ids }` (the answers). |

## Conventions

- Repositories and the frequency repository are created with `create…Repository({ database })` and prepare their statements once in the factory.
- Values are bound parameters. JSON columns (`fsrs_card`, `review_logs.card_before`, `card_after`, settings) are stored as text; the settings repository parses and stringifies them.
- Pure modules take `now` and the other values as parameters and never read the clock or the database.
- Every practice service reads its settings through `practiceSettings.readActiveSettings()`, so the refusal before the migration reads the same everywhere.
- The rules are in `project-quality-standards` and in `docs/FSRS_PRACTICE_ARCHITECTURE.md` (sections 1 to 4, 11 for the reset, 13.1 for the struggling words and 18 for the practice sets, which replace the backlog gate of 10.1, the intake blocks of 12 and 13.2 and the extra new words).
