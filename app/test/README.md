# test

Test suites for `node --test`, run with `npm test` (in Docker, since the host has no Node). Each suite builds its own in-memory database and services with `createTestContext()`. The data-backed suites need a real artifact export, which is personal data and not in git: point `DUTCH_SEED` at it, or they are skipped.

## Files

| File | What it does |
|---|---|
| `seed.js` | Loads the seed export named by `DUTCH_SEED` (default `data/seed/dutch-export.json`) and gives the skip option when it is missing. |
| `database-test-helpers.js` | `createTestContext({ clock, isFsrsFuzzEnabled })`: an in-memory database with all migrations and the domain services built on it. The clock defaults to the system clock; fuzz is off in tests. |
| `domain-services.test.js` | Domain service behaviour: practice results, mistake logging, duplicate skipping, filters, errors, statistics and export. |
| `practice.test.js` | FSRS practice at service level with a fake clock: the migration (dry run and real, one `words` change after the commit), the batch quota and redistribution, grading once per session and its due dates, word errors, chapters and manual priorities, the Amsterdam day boundary including the DST day, the statistics, and the frequency import. |
| `practice-reset.test.js` | `resetPractice` with a fake clock: refused before the migration, a dry run writes nothing, a real reset leaves every word and phrase New with history kept and a batch of exactly 10 new words, skipped days afterwards never grow the list beyond the words started, the pinned word set is cleared, a reset mid-session offers the words and phrases graded earlier in the same session again and lets them be graded once more (a third grade in that session is still refused), a dry run supersedes no review log and a real reset supersedes every one that counted (the logs stay as history), and the database refuses a second log for the same session and word while the first one still counts. |
| `practice-set.test.js` | The practice sets (§18) for words and phrases at service level with a fake clock: a first set is 10 new words split 7, 2, 1; 4 reviews due leave room for 6 new words; 15 due reviews fill the set with the 10 most overdue and the other 5 come in the next set with 5 new words; a pinned set keeps the same words in any session and a word added later waits; a finished word leaves the set and the next set comes the same day; on the next day an unfinished set gives way to its deck words, then the day's reviews, then new words; yesterday's 9 wrong and 1 right give 9 old and 1 new; the round summary counts only the answers since the set opened; and phrases fill their set the same way. |
| `learning-deck.test.js` | The learning deck (the session): the pure rules (2 right answers for a clean word, +1 per again or hard up to 6 keeping the right answers given, a lapse comes back with 3), and through grading with a fake clock: 9 missed and 1 right yesterday keep the 10 words in the session today with no new word, repeats count, the session lasts until all its words are learned and the next 10 come at once, a lapse joins the session without holding back its new words, and the deck rebuild (dry run, positions, a deck word due the day after its last answer). |
| `practice-struggling.test.js` | The struggling-words drill (§13.1) at service level: refused before the migration; the words whose latest answer was again or hard, most errors first then latest first, a later good drops a word out, a never-graded word is left out; and the drill writes nothing (review logs, word errors, cards and statuses are unchanged). |
| `phrase-practice.test.js` | FSRS practice of phrases at service level with a fake clock: refused before the migration, a set of at most 10 New phrases oldest first, the set kept after grades, good > hard > again due dates, one grade per session, the due boundary at the start of tomorrow in Amsterdam, the batch cut to `maxReviews`, the phrase list's status and next due day, the phrase statistics, and an overdue phrase taking a place in the set before the New phrases. |
| `practice-logic.test.js` | Pure practice modules without a database: calendar days and DST, FSRS scheduling and migration cards, chapter and priority rules, queue order, the frequency rank of a Dutch text (apostrophes, numbers, articles), new-word allocation (7, 2, 1 and the redistribution), the tier quota of a block (`calculateNewWordAllowance`: 10 gives 7, 2, 1, 20 gives 14, 4, 2, rounding down), the practice set (`planSetRoom`: old cards first up to the set size, the room left for new cards; `findOpenSet`: open only on its day while an item is pending; the stored set round-trip, a stored value without `item_ids` reading as no set). |
| `import.test.js` | Import of the seed export through the artifact import service: counts, rule mapping, example splitting, idempotence and export round trip; and the refusal once FSRS is set up. |
| `http.test.js` | HTTP behaviour of the full application (`createApplication`): login, cookie and bearer authentication, rate limiting, REST contract, live-update stream, export download, and the REST practice routes (409 before the migration; batch, grades, repeat, stats and preview after it), the phrase practice routes (409 before the migration, batch, grade, repeat and an `answer` refused with 400), the phrase list's `status` and `next_due_on`, the `error_count` of a graded word, and `GET /api/practice/struggling-words` (409 before the migration, then the words to drill, read only). |
| `mcp.test.js` | MCP server over HTTP in the full application: instructions, tool list (including the practice tools), every tool's behaviour, `set_word_priority`'s compact word, the secret-path and bearer authentication, `grade_word` and `grade_phrase` round trips on separate databases (a repeat refused, `error_count` of the graded word, the phrase's status in `list_phrases`), the phrase practice tools in the tool list, and `get_struggling_words` (read-only, listed, a drill that changes no schedule or review log). |
| `environment-configuration.test.js` | The server refuses to start outside test mode when a required secret is missing; the configuration's defaults. |
| `ui-logic.test.js` | Pure browser helpers in `public/logic.js`: escaping, answer checking, `gradeTranslationAnswer` (the grade for a typed Dutch answer in FSRS practice; the article never changes the grade), `revealTranslationAnswer` (the answer shown for «Не знаю»), `pluralizeDays`, `formatDaysAway`, `buildNextReviewLine` (the next-review line under a checked answer), `formatTimesCount` and `buildDeckLine` (the times left in the learning deck, or learned), `formatShortDate` (the table's «Наступне» date), `advanceDrillQueue`, `formatStrugglingDrillButton` and `buildStrugglingDrillEnd` (the struggling-words drill's queue, button text and end line), and rule-body rendering. |

## Conventions

Run the suite with:

```bash
docker run --rm -v /srv/dutch-project/app:/app -v /srv/data/dutch/seed:/seed:ro -e DUTCH_SEED=/seed/dutch-export.json -w /app node:24-bookworm-slim npm test
```
