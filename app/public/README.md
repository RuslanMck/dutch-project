# public

Browser code and static files of the web app, served by Express without a build step. Only browser modules live here; they never import from `src/`. UI text is Ukrainian.

## Files

| File | What it does |
|---|---|
| `index.html` | The app page: header, tab navigation, the static shells of the six tabs (table, cards, practice, rules, phrases, texts), the practice mode select (FSRS, article, «Важкі слова») with its "i" hint, the FSRS summary's «Потренувати важкі слова (N)» button, the struggling-words drill's end block («Тренування завершено…», «Потренувати ще раз»), and the one delete confirmation dialog. |
| `login.html` | The password sign-in page shown before the session cookie exists. |
| `app.js` | UI controller: loads the collections, renders every tab (the words table has no error or status columns), runs the FSRS translation practice session (batch, grades, summary; one session per Amsterdam calendar day, kept in sessionStorage). Each set is practised in two rounds: round 1 UA → NL (`gradeTranslationAnswer`), round 2 NL → UA (`gradeReverseTranslationAnswer`, with «Я мав рацію» holding the grade until pressed or «Далі»); the phrase cards use the same rounds without typing. When the queue runs out it asks the batch again with the same session: new words continue the session, otherwise the summary shows, which can post extra New words. The summary also reads the struggling-words count (`GET /api/practice/struggling-words`) and shows the drill button when it is above zero. The struggling-words drill («Важкі слова») reads that list once per run and posts nothing: the learner types Dutch for each Ukrainian word, wrong, hard and «Не знаю» answers go to the end of the queue, and the end shows how many were right at the first check. The article drill, the cards (today's word batch read-only; the phrase deck asks the phrase batch again at its end), the shared word delete dialog, keeps user input across re-renders and binds events. |
| `api.js` | REST client (same-origin cookie, a 401 goes to `/login`), the practice calls (word and phrase batches, grades, stats, the round summary, the struggling-words list) and the live-update subscription to `/api/events`. |
| `logic.js` | Pure helpers with no DOM access: HTML escaping, answer checking for the article drill (`checkAnswer`), FSRS translation grading (`gradeTranslationAnswer`: `good`, `hard`, `again`; the article never changes the grade, a missing or wrong de/het is named in the message; `revealTranslationAnswer` for «Не знаю»), on answers made comparable by `normalizeAnswerText` (case, typographic quotes, punctuation, spaces) with Levenshtein distance, the Ukrainian day plural and the next-review line, short dates for the words table, rule-body rendering, and the struggling-words drill (`advanceDrillQueue` for the queue order, `buildStrugglingDrillEnd` for the end text, `formatStrugglingDrillButton` for the summary button), and the two-way practice rounds (`gradeReverseTranslationAnswer` and `revealReverseTranslationAnswer` for round 2, `splitIntoRounds` and `planNextRound` for the waiting cards per direction, `orderNextRound` so a word never comes straight back, `formatRoundProgress` and `formatRoundStart` for the round lines, `answerKey` for the answered set). |
| `app.css` | Styles for the app and login pages, with light and dark themes. |
| `icon.svg` | App icon, used as the favicon and in the web manifest. |
| `manifest.webmanifest` | Web app manifest, so the page can be installed on a phone home screen. |

The «Порядок слів» tab (after «Фрази») is a Duolingo-style word-order exercise: the learner taps the shuffled Dutch words of a Ukrainian sentence into the answer line, checks it, and manages the stored sentences (generate, `.md` import, list with delete); its pure state and formatting helpers live in `logic.js`, its REST calls in `api.js`. A rule dropdown above the exercise (`RULE_LABELS`, `formatRuleFilterSummary`, `buildRulesQuery`, `parseStoredRules` for the choice kept in localStorage `wordOrderRules`) filters the set; after «Перевірити» the sentence's schema is shown as boxes coloured by `roleColourClass` (`formatStructureLine` for the text line).
